# منصة مدرسة الفاروق للتواصل الرقمي

نظام تواصل رقمي بين **المدرسة** و**أولياء الأمور والطلبة**، بنفس هوية المكتبة الرقمية (ألوان شعار الفاروق، خطَّي Tajawal وAmiri، الشعارات الثلاثة: مدرسة الفاروق — وزارة التعليم — رؤية عُمان 2040).

المنصة تعمل **فورًا بدون أي إعداد**: تحفظ الطلبات في المتصفح (وضع تجريبي)، وتتحوّل تلقائيًا إلى Firebase لحظي عند نشر قواعد الأمان.

## ٢) تجربة سريعة على جهازك

1. افتح المجلد `Alfarooq-Communications`.
2. اضغط دبل\-كليك على `index.html` (أو ارفعه على أي خادم محلي).
3. اختر بوابة «ولي أمر» أو «طالب» وأرسل رسالة — سيعمل الروبوت وتُفتح طلب `#TK-1045`.
4. افتح `admin.html` في نافذة أخرى ودخول بالإدارة للردّ عليها.

> في هذا الوضع البيانات تُخزَّن في متصفحك فقط (وضع تجريبي)، والردود تظهر لحظيًا بين النوافذ على نفس الجهاز. للمزامنة بين كل الأجهزة اتبع القسم ٥.

**دخول الإدارة**

لوحة الإدارة تعمل بحساب **Firebase Authentication** فقط في النسخة المنشورة. الخطوات في القسم ٥ (البند ٥).

للتجربة على جهازك (`localhost`) فقط، يمكنك وضع كلمة سر مؤقتة في `js/config.js` ← `adminAccount.password`؛ الدخول المحلي **موقوف تلقائيًا على أي نطاق منشور** ولو تُركت كلمة السر:

```js
adminAccount: {
  email: "bader@school.om",
  password: "",            // فارغ = الدخول المحلي معطّل تمامًا
  displayName: "د. بدر بن هلال بن عبدالله الحوسني",
  role: "مدير المدرسة"
},
```

> **لا تنشر كلمة سر في هذا الملف.** يُحمَّل على كل زائر، وأي قيمة فيه تُعتبر علنية.

## ٣) البوابتان ونظام الطلبات المطوّر

**بوابة الطالب** (`chat.html?portal=student`) — مستقلة عن بوابة ولي الأمر:
- ترحيب خاص بالطالب وحقل «اسمك كما في السجل المدرسي» بدل بيانات ولي الأمر.
- التسلسل: اختر **الصف** ← ثم **الشعبة** ← ثم اكتب أو اختر **اسمك**.
- عدد الشُّعب مضبوط: العاشر **٧**، الحادي عشر **١١**، الثاني عشر **١٢** (عدّله من `js/config.js` ← `grades` → `sectionCount`).
- الصف والشعبة **مطلوبان في بوابة الطالب** (مع رقم الجوال)، و**اختياريان** في بوابة ولي الأمر.

**بوابة ولي الأمر** (`chat.html?portal=parent`): اسم ولي الأمر + اسم الابن (اختياري) + الصف والشعبة (اختياري). المدرسة بنين، فكل النصوص تشير إلى «الابن» لا «الابن / البنت».

> كل بوابة تحفظ جلستها نفسها على الجهاز: فتح رابط «بوابة الطالب» لا يقاطع محادثة ولي الأمر والعكس.

**أزرار الأقسام السريعة — كل بوابة لها أزرارها الخاصة:** تظهر فور فتح المحادثة، والضغط على الزر ينقلك إلى القسم مباشرة بدون كتابة رقم (يبقى كتابة الرقم يعمل: ١–٥ لولي الأمر، ١–٦ للطالب).

| بوابة ولي الأمر (`config.parentActions`) | توجَّه إلى | بوابة الطالب (`config.studentActions`) | توجَّه إلى |
|---|---|---|---|
| 🏥 عذر غياب / تقرير طبي | مشرف شؤون الطلبة ومربي الجناح | 📚 استفسار دراسي / واجبات | معلم المادة المعني |
| 🚗 استئذان خروج مبكر | شؤون الطلبة للموافقة | 🏥 عذر غياب | شؤون الطلبة |
| 📊 تقرير المستوى أو السلوك | **إدارة المدرسة** | 🚗 استئذان خروج مبكر | شؤون الطلبة للموافقة |
| 💬 استفسار عام للإدارة | مكتب مدير المدرسة | 💻 دعم تقني للمنصات | فريق تقنية المعلومات |
| ❓ استفسار آخر | **إدارة المدرسة** | 📅 الجدول والاختبارات | شؤون الطلبة + إجابات فورية |
| | | ❓ استفسار آخر | **إدارة المدرسة** |

- حُذف قسم **الأنشطة والمسابقات** (`activities`) من الأزرار ومن قائمة الأقسام في `js/config.js`؛ وبديل الطالب الآن هو الغياب والاستئذان.

- **النبرة مختلفة بحسب الطرف** (`config.botTone`): ترحيب رسمي مُقدَّر لولي الأمر مع طمأنة بوصول الطلب، ونداء مشجع ومباشر للطالب.
- **إجابات فورية للطلبة** (`config.studentFaq`): في خدمة الجدول والاختبارات تظهر أسئلة شائعة تُجاب فورًا داخل المحادثة قبل تحويل أي سؤال للإدارة.
- **محدد الأبناء المتعدد:** ولي الأمر يضيف أبناءه من بوابة الدخول («إضافة ابن»، حتى ٥)، ثم يختار الابن المعني من قائمة أعلى المحادثة؛ يتحدّث اسم الطالب وصفه وشعبته فورًا وتُوجَّه الطلبات لمشرف جناح ذلك الصف. القائمة تظهر فقط عند وجود أكثر من ابن.
- الأقسام الجديدة (`exit-permit`, `schedule`) مضافة إلى قائمة الأقسام المسموحة في `firestore.rules` — **يلزم نشر القواعد** حتى تُقبل كتابتها سحابيًا بعد تفعيل القواعد الجديدة.
- **مرفق التقرير الطبي لم يُبنَ بعد:** رفع الصورة يحتاج قرارًا (Cloud Storage أو مرفق داخل Firestore وكلاهما يغيّر القواعد)، وسيُنفَّذ مع استبدال نظام الطلبات.

**قوائم أسماء الطلبة (اختياري — يُفضَّل تركها فارغة):** في `js/config.js` ← `students` ضع قائمة أسماء لكل «صف-شعبة»:

```js
students: {
  "10-1": ["أحمد بن سالم الرواحي", "خالد بن ماجد آل ثاني"],
  "11-5": ["مازن بن سليمان الرواحي"]
},
```

عند تحديد الصف والشعبة تظهر الأسماء كاقتراحات تحت حقل الاسم، مع إمكانية الكتابة يدويًا.

> **تنبيه خصوصية:** `js/config.js` ملف عام يُحمَّل على كل زائر. وضع أسماء الطلبة الحقيقية فيه يعني كشف قائمة طلبة المدرسة كاملة لأي شخص. الخيارات الآمنة: اتركه فارغًا (يكتب الطالب اسمه يدويًا)، أو اربط الاسم برمز ولي أمر/OTP وتحقّق منه من Firestore بقواعد مقيّدة.

**رقم الجوال إلزامي عند فتح الطلب:** ٨ أرقام فأكثر؛ يُخزَّن بصيغة دولية (+968) ليُستخدم في واتساب والاتصال وإشعار الطالب/ولي الأمر.

**الأهمية (عادية / عاجلة):** تُختار في البوابة، والعاجلة تُعرض فوق غيرها في صندوق الإدارة مع شارة مميزة، وزر في اللوحة يحوّلها بين المستوىين.

**تثبيت الطلب 📌:** زر «تثبيت / إلغاء التثبيت» في اللوحة يبقي الطلب في أعلى الصندوق وفي تبويب «المثبتة».

**أقسام صندوق الطلبات (٦ تبويبات):** الكل · **لم تُفتح** (لم تطّلع الإدارة عليها بعد) · مفتوحة · قيد المعالجة · **المقفلة** · المثبتة — والإحصائيات وأعداد الأقسام تُحتسب داخل القسم المختار أعلاه.

**قسمان في لوحة الإدارة:** «قسم أولياء الأمور» و«قسم الطلبة» (تبويبان أعلى الصندوق)، ولكل قسم إحصائياته الست: لم تُفتح، مفتوحة، قيد المعالجة، مقفلة، عاجلة، الإجمالي. وتضاف فلاتر **الصف** و**الشعبة** للتصفية الدقيقة.

**سجل الحركة:** داخل كل طلب قائمة «سجل الحركة» توثّق: الفتح، اطلاع الإدارة، التثبيت، تغيير الأولوية، تغيير الحالة، التوجيه، والرد — مع اسم الموقّع والوقت.

**أزرار التواصل العاجل في اللوحة:** «واتساب» يفتح `https://api.whatsapp.com/send?phone=968XXXXXXXX&text=…` برسالة جاهزة تحمل اسم صاحب الطلب ورقمها، وزر «اتصال» يفتح `tel:+968…`. يظهر الزران معطّلين إذا لم يكن رقم الجوال صحيحًا.

**زر الطوارئ في البوابتين** يضبطه مقطع `contacts` في `js/config.js`:

```js
contacts: {
  country: "968",
  emergencyWhatsapp: "+968 98132390",   // ← رقم واتساب الإدارة للطوارئ (مضبَّط)
  emergencyName: "غرفة عمليات المدرسة",
  whatsappIntro: "السلام عليكم {name}، معك إدارة مدرسة الفاروق بخصوص الطلب #{ref}."
}
```

> الرقم مضبوط فعلًا على `+968 98132390`، فزرّا «واتساب طارئ» و«اتصال» يعملان في الرئيسية والبوابتين. لو تغيّر الرقم فعدّل هذا الحقل وحده؛ ويبقى الزر معطّلًا تلقائيًا إذا كان الرقم غير صالح.

## ٣-أ) طبقة الحركة — GSAP + ScrollTrigger + Lenis

تعمل على `index.html` وحدها. البوابتان ولوحة الإدارة لم تُحمَّل فيهما أي مكتبة حركة، فوظائف إرسال الطلب والرد لا تتأثر.

**لماذا الملفات داخل `js/vendor/` وليست من CDN؟**
ترويسة CSP في `firebase.json` تسمح بـ `script-src 'self' https://www.gstatic.com` فقط، فأي سكربت خارجي سيُحجب. لذلك GSAP 3.13 وScrollTrigger وLenis 1.1 منسوخة محليًا (١٣٢ كيلوبايت قبل الضغط، وتضغطها الاستضافة إلى نحو ٤٥ كيلوبايت)، وتُحمَّل بخاصة `defer` بعد كل سكربتات المنصة.

**ربط Lenis بمحرّك GSAP (مصدر حركة واحد):**

```js
var lenis = new Lenis({ autoRaf: false, duration: 1.05, easing: ... });
lenis.on("scroll", ScrollTrigger.update);          // تحديث القصّات مع كل تمرير
gsap.ticker.add(function (time) { lenis.raf(time * 1000); }); // Lenis يتقدّم مع GSAP
gsap.ticker.lagSmoothing(0);
```

**المكوّنات الأربعة المطلوبة، وما قابلها:**
React Bits يوزّع مكوّنات React (`.jsx`)، والمشروع صفحات ثابتة بلا React ولا bundler، فلا يمكن «تركيبه» كما هو. نُقلت نفس التأثيرات إلى CSS/JS خالصين بنفس الشكل وألوان الموقع:

| المطلوب | ما نُفّذ |
|---|---|
| عنوان بـ Blur Text | `blurTitle()` يلفّ كلمات `#heroTitle` في `.blur-word` مع الحفاظ على عنصر `.accent` ولونه، ثم `gsap.from(filter: blur(9px), yPercent, stagger .075)` |
| خلفية Light Rays | طبقة `.hero-rays` (٤ أشعة + وهج المصدر + ضباب) بتدرجات ذهبية/خضراء من المتغيرات، `mix-blend-mode: screen`، حركة تمايل ١٣–١٩ ثانية، مع parallax خفيف عبر ScrollTrigger |
| كشف كل section | سمات `data-reveal` (عناوين الأقسام) و`data-reveal-group` (البطاقات والخطوات والمؤشرات والتذييل) بقصّات `once: true` تبدأ عند `top 86%` |
| أرقام تعدّ + زر بـ Star Border | `FarooqMotion.count(el, value)` يعدّ بالأرقام العربية ويُحدّث `data-count-value`؛ والزر الأساسي «بوابة ولي الأمر» أُضيفت له `btn--star` (حلقة دوّارة بـ `@property --star-angle` + نجوم وامضة) بدون تغيير لونه ولا نصه |

**تفضيل تقليل الحركة محترم في ثلاث حالات:**
- `prefers-reduced-motion: reduce`: `motion.js` لا يهيّئ Lenis ولا GSAP إطلاقًا، و`motion.css` يبقي الأشعة والحلقة بلا حركة ويظهر كل المحتوى.
- تعذّل تحميل المكتبات أو استثناء أثناء التهيئة: يُزال صنف `motion-ready` فيبقى كل شيء ظاهرًا (لا محتوى مختفي).
- تغيّر التفضيل أثناء الجلسة: `teardown()` يوقف الـ ticker ويهدم Lenis ويقتل كل القصّات ويمسح التنسيقات المضمّنة.

**للاختبار والضبط:** `FarooqMotion.enable()` تشغّل الحركة رغم تفضيل النظام، و`FarooqMotion.disable()` توقفها وتنظّف. الواجهة العامة `window.FarooqMotion = { active, lenis, count, enable, disable }`.

> ملاحظة توافق: ScrollTrigger 3.13 وLenis 1.1 يستخدمان صياغة ES2015 (وصيغة اختيارية واحدة في Lenis)، أي Chrome 80 / Safari 13.1 فأحدث (2020+). على أجهزة أقدم يفشل تحميل الملفين وتعمل الصفحة كما كانت بلا حركة — لأن كل ملف سكربت معزول عن البقية.

### التنقّل الناعم بين الأقسام والبوابات

طبقة واحدة في `js/utils.js` تستخدمها الصفحات الثلاث، فلا تكرار ولا تعارض:

| الدالة | الوظيفة |
|---|---|
| `FarooqUI.scrollToTarget(node, offset)` | إن كانت Lenis شغّالة على `index.html` تسند إليها الحركة (`lenis.scrollTo`)، وإلا `scrollIntoView({behavior:"smooth"})`. وعند تفضيل تقليل الحركة تنزل فورًا بلا تدرّج. |
| `FarooqUI.stickyOffset()` | ارتفاع الهيدر اللاصق + ١٦، حتى لا يختبئ عنوان القسم خلفه. |
| `FarooqUI.animateOnce(node, class)` | تشغّل صنف حركة مرة واحدة ثم تمسحه بعد ٤٦٠ ملي ثانية؛ لا تعمل أصلًا عند تقليل الحركة. |
| `bindAnchorScroll()` | مستمع واحد على الوثيقة يلتقط كل `a[href^="#"]` (روابط القائمة، رابط «انتقل إلى المحتوى»، أزرار `href="#"` لا تتأثر) ويمنع القفزة الفورية، ويحدّث الشريط العنواني بـ `replaceState` بدل `hashchange`. |

في `chat.html`:
- تبديل التبويبين (ولي الأمر ⇄ الطالب) يحرّك البطاقة وقائمة الخدمات بصنف `is-swapping` بدل إعادة الرسم الفجائية.
- بعد إكمال بوابة الدخول تنزل الصفحة ناعمًا إلى المحادثة بصنف `is-entering`، ومثلها عند زر «طلب جديد».
- أي حقل ناقص في البوابة يُمرَّر إلى `gateError(النص, معرف الحقل)`: تومض حدودته بالذهبي، وتنزل إليه الصفحة، ويأخذ التركيز.
- `bootPhase` يمنع أي حركة أو تنزيل تلقائي عند فتح الصفحة أو استرجاع جلسة محفوظة؛ تبدأ الحركة بعد أول نقرة أو إرسال من المستخدم فقط.

في `index.html`: `html.lenis { scroll-behavior: auto }` في `css/motion.css` يلغي `scroll-behavior: smooth` العامة حتى لا تتنافس المتصفّح وLenis على نفس التمرير، و`js/motion.js` ينزّل ناعمًا إلى القسم المطلوب عبر الشريط العنواني (`#track`) أو عند تغيّره أثناء الجلسة، مع مراعاة ارتفاع الهيدر.

## ٤) نصوص الروبوت والحالات (قابلة للتعديل في نفس الملف)

كل ما ورد في البرومت موجود في `js/config.js` ويمكنك تعديله مباشرة:

- `botGreeting` — ترحيب الروبوت بعد أول رسالة في بوابة ولي الأمر.
- `botGreetingStudent` — ترحيب خاص بالطالب في بوابة الطالب.
- `categories` — أقسام الخدمة ونص اختيار كل قسم: 📚 أكاديمي، 🏥 غياب وتقرير طبي، 📊 تقرير مستوى أو سلوك (**إدارة المدرسة**)، 🏛️ إداري، ⚙️ تقني، 🚗 استئذان خروج مبكر، 📅 جدول واختبارات.
- `notifications.sentToast` — رسالة التأكيد: «✅ تم إرسال استفسارك بنجاح! (رقم الطلب: #TK-1045)…».
- `notifications.replyTitle` / `replyBody` — «🔔 مدرسة الفاروق - تحديث على طلبك».
- `notifications.closedTitle` / `closedBody` — «🟢 مدرسة الفاروق - إغلاق الطلب».
- `ticketRefStart` — رقم بدء الطلبات (حاليًا `1045`).
- `statsSeed` — **أساس أرقام مؤشرات الصفحة الرئيسية**: `open: 7` + `progress: 9` + `closed: 98` = ١١٤ تُجمع مع الطلبات الحقيقية، فيظهر «١٢٤» مثلًا عند وجود ١٠ طلبات فعلية، وكل طلب جديد يزيد العدد تلقائيًا. هذه أرقام عرض فقط لا تُكتب في Firestore ولا تظهر في لوحة الإدارة (لوحة الإدارة تعرض الواقع وحده). للإطفاء اجعل `enabled: false`، أو صفّر الأرقام لإظهار الحقيقي فقط. التعديل في `js/config.js:55`.

الحالات وألوانها: `open` = مفتوحة (أزرق) · `in-progress` = قيد المعالجة (برتقالي) · `closed` = مغلقة (أخضر)، مع زر **«إغلاق الطلب وحل الاستفسار»** في لوحة الإدارة.

## ٥) الربط بـ Firebase (قاعدة بيانات + إشعارات لحظية)

المشروع المخصّص للمنصة: **`farooq-communications`** (منفصل عن موقع المدرسة والمكتبة حتى لا تختلط البيانات).
اسم المشروع محفوظ في ملف `.firebaserc`. إن غيّرته، عدّله هناك وفي `js/config.js`.

**١. إنشاء المشروع**
- افتح https://console.firebase.google.com ← **Add project** ← الاسم `farooq-communications` ← إيقاف Google Analytics (اختياري) ← **Create project**.

**٢. تسجيل تطبيق ويب وأخذ `firebaseConfig`**
- ⚙ **Project settings** ← **General** ← **Your apps** ← أيقونة `</>` ← سجّل التطبيق باسم `farooq-communications`.
- انسخ كائن `firebaseConfig` والصق قيمه في `js/config.js` (الحقول: `apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`).

**٣. تفعيل Firestore (مخزن الطلبات)**
- **Build ← Firestore Database ← Create database** ← اختر أقرب منطقة (مثل `eur5`) ← **Start in production mode** ← Finish.

**٤. تفعيل Realtime Database (طبقة الإشعارات والعدّادات)**
- **Build ← Realtime Database ← Create Database** ← نفس المنطقة ← **Start in locked mode** ← Enable.
- انسخ الرابط الذي يظهر بصيغة `https://farooq-communications-default-rtdb.firebaseio.com/`.
- الصقه في `js/config.js` ← `firebaseConfig.databaseURL`. **بدون هذا الحقل تبقى الإشعارات اللحظية معطّلة ويعمل الموقع بالوضع المحلي.**

**٥. تفعيل Authentication (لدخول الإدارة الحقيقي)**
- **Build ← Authentication ← Get started** ← فعّل **Email/Password** ← ثم **Users ← Add user** بحسابين:
  - حساب المدير: البريد `bader@school.om` وكلمة سر طويلة وقوية (١٦ حرفًا فأكثر) — لا تستخدم كلمة السر التي كانت مكتوبة في النسخة التجريبية.
  - حساب عام بلا اسم (للواء/الموظف): بريد آخر، واترك **Display name** فارغًا.
- ⚠️ كلمة `bader9936` اعتُبرت مكشوفة: لا تُستخدم في أي حساب.
- **تم وضع الـ UID الخاص بكما مسبقًا** في `firestore.rules` و`database.rules.json`، وفي `js/config.js` ← `adminAccounts` (الأول يعرض باسم المدير، والثاني ترحيب عام بلا اسم). إن أنشأت الحسابات الجديدة لاحقًا فحدّث الـ UID في هذه المواضع الأربعة.
- `useFirebaseAuth: true` — مُفعّلة فعلًا في `js/config.js`، لا تغيّرها.

**٦. نشر القواعد (الأهم)**
- Firestore: **Firestore Database ← Rules** ← الصق كامل محتوى `firestore.rules` ← **Publish**.
- Realtime Database: **Realtime Database ← Rules** ← الصق كامل محتوى `database.rules.json` ← **Publish**.
- أو بالنشر الآلي من الوصف في القسم ٨: `firebase deploy --only firestore:rules,database:rules`.

**٧. اختبار الربط**
- افتح `index.html` — الشريط العلوي يجب أن يقول **متصل سحابيًا — تحديث لحظي**.
- أنشئ طلب من بوابة ولي الأمر بجوال حقيقي، ثم افتح `admin.html` في نافذة/جهاز آخر: تظهر الطلب لحظيًا.
- ردّ من الإدارة ← عند صاحب الطلب يظهر الإشعار فورًا في نفس الصفحة (وداشبورد المتصفح إن منح الإذن).
- من الرئيسية: متابعة الطلب تحتاج **رقم الطلب + رقم الجوال المسجَّل** معًا.

> **ما الذي تغيّر في الخصوصية؟** لم يعد أي زائر يقرأ صندوق الطلبات كاملًا. كل طلب تُفتح بمعرّف مستندي لا يُعرف إلا لصاحب الجلسة، والمتابعة العامة تتم بمفتاح `(رقم الطلب + رقم الجوال)` مفهرس في Realtime Database، والعدّادات في الرئيسية تُقرأ من عقدة `stats` التي لا تحتوي أسماءً ولا أرقام جوّال.

## ٦) الأمان — اقرأ هذا قبل النشر الرسمي

**ما تم تنفيذه في الكود والقواعد (إصدار ٢٩/١٠/٢٠٢٦):**

- لا كلمة سر في الملفات العامة: `adminAccount.password` فارغة، والدخول المحلي يعمل على `localhost` فقط وموقوف على أي نطاق منشور.
- لا hint في صفحة الدخول: أُزيل البريد المبدئي من `admin.html`، وصندوق الإدارة مخفي قبل نجاح الدخول.
- Firestore: الزائر ينشئ طلب «مفتوحة» غير مثبّتة بلا حقول إدارة، ولا رسائل تنتحل صفة الإدارة عند الإنشاء.
- Firestore: رسائل الزائر **إلحاقية فقط** — لا حذف، لا تعديل رسالة سابقة، لا زيادة عدد رسائل الإدارة.
- Firestore: عدّاد الرقم المرجعي يقبل زيادة بواحدة فقط، فلا يمكن تضخيمه لإيقاف إنشاء الطلبات.
- Realtime Database: **قائمة بيضاء** لكل عقدة (`$other: false`) مع تحقق من نوع كل حقل وطوله وقيمته — لا يمر أي حقل غير متوقع.
- `tokens` (رموز الأجهزة) لا تُقرأ إلا بحساب الإدارة المسجّل، بدل «أي حساب».
- ترويسات أمان على Firebase Hosting: CSP (يمنع تضمين الصفحة في إطار خارجي)، `nosniff`، `Referrer-Policy`، `Permissions-Policy`، `X-Frame-Options`، HSTS.
- عامل الخدمة لم يعد يخزّن إلا ملفات الموقع نفسه (لا طلبات Firebase ولا لوحة الإدارة ولا الردود غير الناجحة).

**الخطوات الصحيحة للنشر الرسمي (لا تُنشر قبل إتمامها):**

1. **أنشئ حسابين في Firebase Authentication:**
   - Firebase Console ← **Build ← Authentication ← Get started**.
   - تبويب **Users** ← **Add user** ← المدير: البريد `bader@school.om` وكلمة سر طويلة وقوية (١٦ حرفًا فأكثر).
   - ثم **Add user** للحساب العام (بريد العمل المشترك) واترك **Display name** فارغًا — تظهر اللوحة عنده بالترحيب العام بدون اسم.
2. **الـ UID مضاف مسبقًا:** حسابا الإدارة موضوعان فعلًا في `isEditor()` داخل `firestore.rules`، وفي قراءة `tokens` داخل `database.rules.json`، وفي `adminAccounts` داخل `js/config.js` — عندهما فقط يستطيع حساب الإدارة سرد صندوق الطلبات (`allow list: if isEditor()`) وقراءة رموز الأجهزة، بينما يبقى للزائر: إنشاء طلب، والرد عليها، وفتح طلبه بمعرّف مستنده. إن غيّرت الحسابات فحدّث الـ UID في المواضع الثلاثة.
3. **التحقق الحقيقي مُفعّل:** `useFirebaseAuth: true` ثابت في `js/config.js` — لو رجعته `false` تبقى قائمة الطلبات في لوحة الإدارة غير متاحة سحابيًا وتظهر رسالة «صندوق الإدارة مقفول».
4. **عطّل التسجيل الذاتي** في Authentication (حتى لا يستطيع أي شخص إنشاء حساب والوصول لما هو مقيّد بـ `auth != null`)، وفعّل **Email Enumeration Protection**.
5. **فعّل App Check** (reCAPTCHA v3) وطبّقه enforce على Firestore وRealtime Database — هذا هو الرد العملي على إغراق الكتابة واستنزاف الحصة المجانية.
6. **قيّد مفتاح الـ API** في Google Cloud Console ← Credentials بنطاق موقعك فقط، وضع تنبيه ميزانية في Billing.

**مخاطر متبقية يعرفها صاحب القرار (تحتاج تصميمًا إضافيًا لا تعديل سطر):**

- **سرية الطلب تعتمد على secrecy المعرّف**: من يعرف معرّف وثيقة Firestore يستطيع قراءتها. الحل الجذري: `signInAnonymously()` وحقول `ownerUid` في الطلب وقصر `get` على صاحبها أو الإدارة.
- **متابعة الطلب برقمها + الجوال** قابلة للتخمين نظريًا (الرقم تسلسلي والجوال العماني ٨ خانات). الحل: رمز وصول عشوائي يُعرض لصاحب الطلب، أو OTP على الجوال، أو رمز ولي أمر مطبوع من المدرسة.
- **لا تحقق من هوية صاحب الاسم/الجوال**: أي شخص يفتح طلب باسم أي طالب. الأخطر في طلبات الاستئذان — يجب ألا تُعتمد إلا بتأكيد هاتفي من الإدارة.
- **لا سياسة خصوصية ولا مدة احتفاظ**: المحادثات تُحفظ بلا سقف. يلزم صفحة سياسة خصوصية وموافقة صريحة وخطة أرشفة/حذف (نهاية العام الدراسي مثلًا) وموافقة الوزارة على تخزين بيانات قاصرين.
- **إداري واحد فقط** (UID واحد في القواعد) = نقطة فشل. للتوسع: Custom Claim باسم `admin` وعدة حسابات.

## ٧) نظام الإشعارات

**الطبقة الأولى — لحظية داخل الصفحة (تعمل بمجرد ضبط `databaseURL`):**
- عند ردّ الإدارة أو تغيير الحالة أو الإغلاق يُنشر حدث في `events/{ticketId}` بقاعدة Realtime Database.
- بوابة التواصل مشتركَة بطلب صاحبها فقط (`Store.subscribeTicket`)، فتصله الرسالة والإشعار فورًا دون تحديث الصفحة.
- الإدارة ترى الطلبات الجديدة لحظيًا ويصلها تنبيه «طلب جديد في صندوق الإدارة».
- عدّادات الرئيسية تُقرأ من `stats` (رقم مرجعي + حالة + بوابة — بلا أسماء ولا أرقام).

**الطبقة الثانية — إشعار المتصفح (Notification API):**
- يطلب الموقع الإذن عند تعبئة البيانات (`#notifyConsent`) أو من زر «تفعيل الإشعارات» داخل المحادثة.
- بعد المنح تظهر الإشعارات بالعنوان والنص المحدَّدين، والنقر عليها يفتح الطلب عبر `sw.js`.

**الطبقة الثالثة — Firebase Cloud Messaging (اختيارية، للوصول والصفحة مغلقة):**
1. **Project settings ← Cloud Messaging** ← تأكد أن رسائل الويب مفعّلة، ثم **Web configuration ← Generate keys pair** وانسخ **Web Push certificates**.
2. في `js/config.js`: `fcm.vapidKey: "المفتاح المنسوخ"` و `fcm.enabled: true`، وحدّث `messagingSenderId`/`appId` لمشروع التواصل.
3. يسجّل الموقع رمز الجهاز تلقائيًا في `tokens/{deviceId}` بعد منح الإذن.
4. الإرسال التلقائي عند كل ردّ يحتاج **Cloud Functions** (غير متاحة في خطة Spark المجانية). على Spark:
   - الإشعارات اللحظية داخل الصفحات المفتوحة تعمل كما في الطبقة الأولى، و
   - يمكن للإدارة إرسال broadcast يدوي من **Messaging ← Create a campaign** عند الحاجة.

> ملاحظة خطة Spark: إن كانت المنصة على خطة مجانية بلا Functions، فالإشعار الحقيقي يعمل طالما كان المتصفح مفتوحًا (تابع أو PWA مثبّتة على سطح المكتب تعمل في الخلفية). الترقية إلى Blaze تُفعّل الإرسال التلقائي لكل جهاز.

## ٨) النشر على الإنترنت

**المستخدمة فعلًا الآن — Vercel:** الموقع منشور على **https://farooq-communications.vercel.app** (مشروع `ali-ef08/farooq-communications`).

1. ثبّت الأدوات مرة واحدة: `npm install -g vercel` ثم `vercel login`
2. من داخل مجلد النشر `Alfarooq-Communications-Publish`:
   ```bash
   vercel deploy public --prod --yes --project farooq-communications
   ```
   لا بناء ولا حزم: ملفات `public/` تُرفع كما هي، و`public/vercel.json` يطبّق الترويسات الأمنية نفسها الموجودة في `firebase.json`.
3. النطاق الخاص لاحقًا: مشروعك في Vercel ← **Settings ← Domains** ← أضف `comms.alfarooqom.com` واتبع سجلات DNS، ثم أضف النطاق إلى Authorized domains في Firebase.
4. **لا تنسَ**: رفع رقم `CACHE` في `js/sw.js` بعد كل تعديل في `js/` أو `css/`، وإلا بقيت النسخة القديمة في أجهزة الزوّار.

> القواعد (`firestore.rules` و`database.rules.json`) لا تُنشر مع Vercel — انشرها من Firebase Console ← Rules ← الصق ← Publish.

**الطريقة البديلة — Firebase Hosting (نفس مشروع قاعدة البيانات، ينشر الموقع والقواعد معًا):**

1. ثبّت Node.js ثم أدوات Firebase: `npm install -g firebase-tools`
2. من داخل المجلد `Alfarooq-Communications`:
   ```bash
   firebase login                 # تسجيل الدخول بحساب جوجل
   firebase use farooq-communications
   firebase deploy                # ينشر الموقع + firestore.rules + database.rules.json معًا
   ```
3. يعطي الأمر رابطًا جاهزًا مثل `https://farooq-communications.web.app`
4. نطاق خاص: **Hosting ← Add custom domain** (مثلاً `comms.alfarooqom.com`)، ثم أضف سجل DNS الذي يطلبه جوجل.

> ملفا `firebase.json` و`.firebaserc` جاهزان في المجلد، ولا حاجة لأي أمر إعداد. للإشعارات يجب أن يكون النشر على **HTTPS** (localhost يعمل أثناء التجربة).

**بعد النشر:** أضف النطاق في Firebase Console ← Authentication ← Settings ← **Authorized domains** (بدونه يفشل دخول الإدارة)، وحدّث `siteUrl` في `js/config.js` إن رغبت، وتأكد من حالة «متصل سحابيًا» في شريط الوضع.
